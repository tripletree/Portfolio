01Product

Two surfaces, one job: give a truck somewhere to park.

The driver app runs in a phone browser: choose a yard and dates, enter a plate, pay by card, bank debit, Apple Pay or Google Pay, receive a gate code. The operator console serves the yard operator: bookings, capacity, pricing, customers, plus AI cameras that read plates and the vehicle records they produce.

This project has no development schedule in the traditional sense. Every feature and defect is a ticket, and every ticket travels the same pipeline.

02Pipeline

The life of one ticket.

People appear at both ends only: stating what is wanted at the start, reading evidence and signing off at the end. Planning, dispatch, implementation, gates and review in between are done by agents following skills. Below is a replay of a real kind of defect ticket going all the way through.

03Skills

I don’t write the code. I write how agents work.

A skill is a manual written for an agent: when to load it, what it owns, what it must not do, and what counts as done. Agents match and load skills from the task description. The ten skills fall into four groups: task orchestration, shared rules, knowledge, tooling.

04Evidence

I read evidence, not diffs.

An agent saying “fixed” counts for nothing. Every change must pass static gates (lint with zero warnings, type check, secret scan, dead-code check), pass end-to-end tests named after behaviour, and attach a before/after from a real browser with the raw measurements.

  • Tests are named after behaviour. Ticket numbers live only in a traceability table, so the test suite reads as the requirements.
  • Local and CI share one verdict. A warning blocks, which ends “passes locally, fails in CI”.
  • Budgets are gates. Exceed the bundle size or performance budget and the pull request cannot merge.
05My part

The human in the pipeline.

I do three things. First, define the product: flows, screens and the acceptance criteria on every ticket. Second, write the skills: turn each incident review into a rule agents will follow next time. Third, sign off: read the evidence and decide whether the ticket is actually done.

The method transfers to other teams: the skills, ticket contract, gates and evidence rules form a package that can be delivered.
